## 阶段 0：环境搭建 & 骨架验证

**目标**：确保开发环境可用，后端能启动、前端能连通后端。

### 步骤

1. **安装前置工具**
   - JDK 17+
   - Maven 3.8+
   - Node.js 18+
   - MySQL 8.x

2. **创建数据库**
   ```sql
   -- 在 MySQL 中执行
   source backend/src/main/resources/db/schema.sql
   ```

3. **修改数据库配置**
   - 文件：`backend/src/main/resources/application-dev.yml`
   - 确认 `username`、`password`、数据库 URL 正确

4. **启动后端**
   ```bash
   cd backend
   mvn spring-boot:run
   ```
   - ✅ 验收：控制台输出 `Started CampusApplication` 且无报错

5. **启动前端**
   ```bash
   cd frontend
   npm run dev
   ```
   - ✅ 验收：浏览器打开 `http://localhost:5173`，页面正常显示

6. **验证前后端联通**
   - 打开浏览器 DevTools → Network
   - 首页加载时应发出 `GET /api/events` 请求
   - ✅ 验收：请求返回 `{"code":200, "data":{"records":[], ...}}`（空列表正常）

## 阶段 1：用户认证模块

**目标**：完成注册、登录、Token 鉴权的完整闭环。

### 后端验证清单

| # | 验证项 | 方法 | 预期结果 |
|---|---|---|---|
| 1.1 | 注册接口 | POST `/api/auth/register` | 返回 code=200，数据库 user 表新增一条 |
| 1.2 | 用户名重复 | 同用户名再注册一次 | 返回错误提示 |
| 1.3 | 登录接口 | POST `/api/auth/login` | 返回 token |
| 1.4 | 密码错误 | 错误密码登录 | 返回"用户名或密码错误" |
| 1.5 | 获取当前用户 | GET `/api/users/me` (带 Token) | 返回用户信息（不含密码） |
| 1.6 | 无 Token 访问 | GET `/api/users/me` (不带 Token) | 返回 401 |

### 前端开发步骤

1. **登录页联调**
   - 文件：`frontend/src/views/Login.vue`
   - 测试：填写用户名密码 → 点击登录 → Token 存入 localStorage → 跳转首页
   - 验证：导航栏显示用户名和"退出"按钮

2. **注册页联调**
   - 文件：`frontend/src/views/Register.vue`
   - 测试：填写信息 → 注册成功 → 跳转登录页

3. **导航栏状态**
   - 文件：`frontend/src/components/Navbar.vue`
   - 验证：未登录显示"登录/注册"，已登录显示用户名 + 退出

4. **路由守卫**
   - 验证：未登录访问 `/profile` → 重定向到登录页
   - 验证：已登录访问 `/login` → 重定向到首页

### ✅ 阶段验收
- 用默认管理员 `admin / admin123` 登录成功
- 注册新普通用户并登录成功
- 退出后导航栏恢复为"登录/注册"

## 阶段 2：活动管理模块（仅管理员）

**目标**：管理员可以创建、编辑、删除活动，所有用户可以浏览活动列表和详情。

### 后端验证清单

| # | 验证项 | 方法 | 预期结果 |
|---|---|---|---|
| 2.1 | 创建活动 | POST `/api/events` (ADMIN Token) | 返回活动数据，status=OPEN |
| 2.2 | 普通用户创建 | POST `/api/events` (USER Token) | 返回 403 |
| 2.3 | 活动列表 | GET `/api/events?page=1&size=10` | 返回分页数据 |
| 2.4 | 分类筛选 | GET `/api/events?category=LECTURE` | 仅返回讲座类活动 |
| 2.5 | 关键词搜索 | GET `/api/events?keyword=xxx` | 返回标题匹配的活动 |
| 2.6 | 活动详情 | GET `/api/events/{id}` | 返回完整活动信息 |
| 2.7 | 编辑活动 | PUT `/api/events/{id}` (ADMIN) | 活动信息更新 |
| 2.8 | 删除活动 | DELETE `/api/events/{id}` (ADMIN) | is_deleted 变为 true |
| 2.9 | 时间校验 | 创建时 endTime < startTime | 返回错误提示 |

### 前端开发步骤

1. **创建活动页**
   - 文件：`frontend/src/views/EventCreate.vue`
   - 仅管理员可见（导航栏"发布活动"按钮）
   - 表单校验：所有必填项 + 时间逻辑校验
   - 创建成功后跳转首页

2. **活动列表页**
   - 文件：`frontend/src/views/Home.vue` + `frontend/src/components/EventCard.vue`
   - 卡片展示：标题、分类标签、状态标签、地点、时间、报名人数
   - 搜索框输入 → 回车搜索
   - 分类下拉 + 状态下拉筛选
   - 分页 (每页 10 条)

3. **活动详情页**
   - 文件：`frontend/src/views/EventDetail.vue`
   - 展示完整信息（地点、时间、人数、描述等）
   - 管理员可见"编辑"和"删除"按钮

4. **编辑活动页**
   - 文件：`frontend/src/views/EventEdit.vue`
   - 进入时回填已有数据
   - 保存后跳转详情页

5. **删除活动**
   - 二次确认弹窗 → 调用删除接口 → 跳转首页

### ✅ 阶段验收
- 管理员创建 3-5 条不同分类的活动
- 首页列表正确展示，搜索/筛选功能正常
- 点击卡片进入详情页，信息完整
- 编辑活动后信息更新，删除后列表中消失

## 阶段 3：活动报名模块

**目标**：用户可以报名和取消报名，名额扣减并发安全。

### 后端验证清单

| # | 验证项 | 方法 | 预期结果 |
|---|---|---|---|
| 3.1 | 报名 | POST `/api/events/{id}/registrations` | current_participants +1 |
| 3.2 | 重复报名 | 同一用户再次报名 | 返回"已报名" |
| 3.3 | 名额已满 | 达到 max 后报名 | 返回"名额已满" |
| 3.4 | 取消报名 | DELETE `/api/events/{id}/registrations` | current_participants -1 |
| 3.5 | 未报名取消 | 未报名用户取消 | 返回"未报名" |
| 3.6 | 活动已开始 | 状态非 OPEN 时报名 | 返回错误 |
| 3.7 | 我的报名 | GET `/api/users/me/registrations` | 返回已报名列表 |

### 前端开发步骤

1. **详情页报名交互**
   - 文件：`frontend/src/views/EventDetail.vue`
   - 状态判断：
     - 未登录 → 隐藏报名按钮或点击跳转登录
     - 已报名 → 显示"取消报名"
     - 未报名 + 名额未满 → 显示"报名参加"
     - 名额已满 → 按钮置灰"名额已满"
     - 活动非报名中 → 隐藏报名按钮
   - 需要新增接口：检查当前用户是否已报名某活动（或将此信息合并到活动详情接口）

2. **报名状态 API 补充**（可选优化）
   - 后端可在 `GET /api/events/{id}` 返回中增加 `isRegistered` 字段（需要当前用户 ID）
   - 或前端单独调用 `GET /api/users/me/registrations` 对比

### ✅ 阶段验收
- 普通用户可成功报名，按钮切换为"取消报名"
- 取消报名后人数 -1
- 名额满后其他用户无法报名
- "我的报名"列表正确显示

## 阶段 4：评论模块

**目标**：用户可在详情页发表和删除评论，管理员可删除任意评论。

### 后端验证清单

| # | 验证项 | 方法 | 预期结果 |
|---|---|---|---|
| 4.1 | 发表评论 | POST `/api/events/{id}/comments` | 返回评论数据 |
| 4.2 | 内容为空 | 提交空内容 | 返回校验错误 |
| 4.3 | 超过 500 字 | 提交超长内容 | 返回校验错误 |
| 4.4 | 评论列表 | GET `/api/events/{id}/comments?page=1&size=20` | 倒序分页 |
| 4.5 | 删除自己评论 | DELETE `/api/comments/{id}` (作者) | 删除成功 |
| 4.6 | 删除他人评论 | DELETE `/api/comments/{id}` (非作者非管理员) | 返回 403 |
| 4.7 | 管理员删评论 | DELETE `/api/comments/{id}` (ADMIN) | 删除成功 |

### 前端开发步骤

1. **评论表单**
   - 文件：`frontend/src/views/EventDetail.vue`（评论区域）
   - 未登录 → 提示"请先登录"
   - 输入框 + 字数统计 (500 字限制) + 发表按钮
   - 发表成功后清空输入框，刷新列表

2. **评论列表**
   - 展示：用户名 + 时间 + 内容
   - 自己的评论显示"删除"按钮
   - 管理员所有评论都显示"删除"按钮
   - 分页（每页 20 条）

### ✅ 阶段验收
- 发表评论后实时出现在列表顶部
- 作者可删除自己评论
- 管理员可删除任意评论
- 访客可查看评论但不能发表

## 阶段 8：测试 & 部署

### 测试

1. **后端接口测试**
   - 使用 Postman / Apifox 对所有 API 做手动测试
   - 覆盖正常流程 + 异常流程

2. **前端联调测试**
   - 走通完整业务流程：
     ```
     注册 → 登录 → 浏览列表 → 查看详情 → 报名 → 评论 → 收藏
     → 个人中心查看 → 取消报名 → 退出
     ```
   - 管理员流程：
     ```
     登录(admin) → 发布活动 → 编辑活动 → 删除评论 → 删除活动
     ```

3. **边界测试**
   - 并发报名（多个浏览器同时报名最后一个名额）
   - 超长文本输入
   - Token 过期后的行为

### 部署（可选）

1. **后端打包**
   ```bash
   cd backend
   mvn clean package -DskipTests
   java -jar target/campus-activity-0.0.1-SNAPSHOT.jar
   ```

2. **前端打包**
   ```bash
   cd frontend
   npm run build
   # dist/ 目录部署到 Nginx
   ```

3. **Nginx 配置**
   ```nginx
   server {
       listen 80;
       
       location / {
           root /path/to/frontend/dist;
           try_files $uri $uri/ /index.html;
       }
       
       location /api/ {
           proxy_pass http://localhost:8080;
       }
   }
   ```

## 附录：开发中可能需要补充的功能点

## 推荐开发顺序提示

> [!TIP]
> **按"后端接口 → Postman 验证 → 前端联调"的节奏推进每个模块。**
> 先确保后端逻辑正确，再做前端对接，避免前后端同时出问题时难以定位。

> [!IMPORTANT]
> **每完成一个阶段就 git commit**，方便回退。建议的 commit 粒度：
> - `feat: 完成用户认证模块`
> - `feat: 完成活动管理模块`
> - `feat: 完成报名功能`
> - ...
